# Working in this repository

Generated by `emporix-setup`. Settings: `ai-setup.json`. Product knowledge:
`PROJECT.md` → `ai-project-knowledge/`. Re-run `/emporix-setup` when the stack
or commands change; `/emporix-setup --rescan` when the business logic changes.
Every claim below names its source file; `unknown` means no evidence was found.

This is a monorepo of independent Management Dashboard remotes, one Vite app per top-level folder. There is no root `package.json`, no workspace tool, and no root app. Install, build, test, and run each remote from its own folder. Agent rules live only at the repository root; remotes carry no rule copies. `agentic-ai/` has its own `AGENTS.md` and `ai-setup.json`; they apply when you work only inside that folder.

## Validation gate

Run in order before declaring work done (`ai-setup.json` → `validation.commands`):

1. The changed-remotes loop in `ai-setup.json`. From the repository root it lists the remotes that differ from `origin/master` (committed, staged, unstaged, and untracked files). It stops with an error when the base or the diff cannot be read. In each remote it runs `npm ci` when `node_modules` is missing, then `typecheck` (if present), `npx eslint .` (not `npm run lint`, which is `eslint . --fix` in `agentic-ai`), `test:run` (if present), and `build:dev`. That is the extension gate of `.claude/skills/md-module-extraction/SKILL.md` (Phase 4) plus the `npm ci` and `build:dev` each `*-firebase-preview.yaml` runs on a PR. Changes outside remote folders (docs, workflows, knowledge) run nothing.

Where the repository instructions above are more specific than the frontend rules, the repository instructions win. Known conflicts, left as they are:

- `api-data` keeps API code in `src/api/` only and shows `VITE_API_BASE_URL`. The remotes use `VITE_API_URL`, `src/api/bootstrap.ts`, and `src/hooks/api/*` around `@emporix/api-calls` (`md-extension-migration.md` § API); legacy `agentic-ai` keeps `src/services/`.
- `primereact` versus `module-federation` § Management Dashboard Remotes and `md-extension-migration.md` § UI policy: never add PrimeReact to a remote. Apply `primereact` only in `agentic-ai`, `dashboard`, `statistics`, `algolia-synonyms`.
- `testing` runs `npm run test`, which is watch mode here; use `npm run test:run` (`md-module-extraction` Phase 4).
- `module-federation` asks for a camelCase federation name and a pinned `strictPort`. `agentic-ai`, `dashboard`, `statistics` use `name: 'extension'`, and those three plus `users-and-groups` pin no port. Its § Management Dashboard Remotes says not to change that as a drive-by.
- A missing component-library component: `md-extension-migration.md` and the extraction skill name a `migrate-to-component-library` skill that is not installed. The current flow is `emporix-frontend-standards` → `references/library/workflow.md`. Both ask the user first.
- `core` style (no `React.FC`, `readonly` props, helpers in `src/helpers/`) applies to new code. Ported Management Dashboard and Tier 1 code follows the extraction skill and playbook.
- `i18n` asks for `feature.section.label` keys; remotes keep the keys of the ported MD screens (`md-extension-migration.md` § i18n).

Rules observed in those files (not inferred from framework habit):

## App

- Kind: ui; auth: none in config. Each remote takes `tenant` and `token` from the host `appState`; the standalone shell asks for tenant, token, and language in a dev dialog (`<remote>/src/App.tsx`).
- Start: per remote, `npm run dev` in its folder (ports in **Remotes**). There is no single app, so `app.start` and `app.baseUrl` stay empty and QA skills ask. Inside the host, point `VITE_{MODULE}_URL` at `http://localhost:<port>/assets/remoteEntry.js` (`labels/README.md`, `products/README.md`). Ready path: `/`.
- API contract: none in this repo; REST paths live in `@emporix/api-calls`. Local docs: `<remote>/README.md`, `docs/`; the root `README.md` still describes one app on port 5173. Published docs: none mapped at the root (`docs.targets` omitted; `agentic-ai/ai-setup.json` maps its own).
