Read-only operator home for one tenant. The Management Dashboard loads it as a Vite module-federation remote named `extension`, file `remoteEntry.js`, expose `./RemoteComponent` (`dashboard/vite.config.ts`, `dashboard/README.md`). Package name is `@emporix/dashboard-extension` (`dashboard/package.json`). The only persisted write is the widget layout. Business entities are fetched and linked into the host app.

Actor: a signed-in operator. The host passes `tenant`, `token`, `language`, `currency`, `contentLanguage`, `user`, and optional `permissions` (`dashboard/src/shared/models/AppState.model.ts`). `RemoteComponent` renders the page only when `tenant` and `token` are both set; otherwise it shows “Missing required configuration (tenant or token).” Missing language becomes `en`, missing currency becomes EUR, missing `contentLanguage` becomes `en`, missing user becomes `{ userId: '', termsAndConditions: true }` (`dashboard/src/RemoteComponent.tsx`). `DashboardPage` forwards only `tenant`, `language`, `token`, `currency.id`, and `permissions` into dashboard context. `contentLanguage` and `user` are dropped there (`dashboard/src/dashboard/pages/DashboardPage.tsx`). Standalone `npm run dev` asks for tenant, token, and language, stores those three in `sessionStorage`, and sends currency EUR plus `userId: 'dev'` with no permissions (`dashboard/src/App.tsx`, `dashboard/README.md`).

## What the operator can do

Filter the board by an optional site and a date range, then read the widgets below. Customize mode adds a widget, removes one, and allows drag and resize on a 24-column grid with 40px rows. Drag and resize are off outside that mode (`dashboard/src/dashboard/components/DashboardGrid.tsx`, `dashboard/WIDGETS.md`). Layout edits stay in memory until a save button. “Save custom configuration” writes `localStorage` key `md_dashboard_layout`. “Save global configuration” is shown only when `permissions.systemPreferences.manager === true` and writes tenant configuration key `dashboard_layout`. “Reset to defaults” clears that `localStorage` key, restores `DEFAULT_GRID_LAYOUT`, and, for a manager, also writes that default to the tenant (`dashboard/src/dashboard/pages/DashboardPage.tsx`, `dashboard/src/dashboard/hooks/useDashboardLayout.ts`, `dashboard/src/dashboard/helpers/layout.helpers.ts`).

Each widget is renderless: no props, data from context and hooks (`dashboard/WIDGETS.md`). A widget whose id ends with `kpi` (any case) uses the compact KPI card (`dashboard/src/dashboard/helpers/layout.helpers.ts`). A thrown widget error is caught per card, logged in dev, and can be retried (`dashboard/src/dashboard/components/WidgetErrorBoundary.tsx`). The page itself sits in `ErrorBoundary` (`dashboard/src/RemoteComponent.tsx`).

Record links are plain `<a href>` into the host, not in-app routes (`dashboard/src/dashboard/data/routes.ts`):

| Target | Path |
|---|---|
| Customer list / one customer | `/apps/management/customers`, `/apps/management/customers/{id}` |
| Order list / one order | `/apps/management/orders`, `/apps/management/orders/{id}` |
| Quote list / one quote | `/apps/management/quotes`, `/apps/management/quotes/{id}` |
| Return list / one return | `/apps/management/returns`, `/apps/management/returns/{id}` |
| Cart list / one cart | `/apps/management/carts`, `/apps/management/carts/{id}` |
| Employee list / one user | `/administration/users-and-groups`, `/administration/users-and-groups/users/{id}` |

Customer links use `customer.id`. Employee links use `employee.id`. Cart customer links use `customerId`, including an empty id (`dashboard/src/dashboard/widgets/CustomersWidget/CustomersWidget.tsx`, `dashboard/src/dashboard/widgets/EmployeesWidget/EmployeesWidget.tsx`, `dashboard/src/dashboard/widgets/AbandonedCartsTableWidget/AbandonedCartsTableWidget.tsx`).

## Filters

Site list comes from `GET /site/{tenant}/sites`. The dropdown label is `{name} - {code}`, it can be cleared, and it starts empty. `fetchSites` returns the parsed collection as `DashboardSite` and does not set `default` or drop `active: false`. Whether the API already omits inactive sites is unknown (`dashboard/src/dashboard/api/sites.api.ts`, `dashboard/src/dashboard/hooks/useSites.ts`, `dashboard/src/dashboard/components/DashboardToolbar.tsx`, `dashboard/src/dashboard/context/DashboardContext.tsx`).

A selected site is sent as a restriction. Stats use query param `restriction={code}`. Orders, quotes, and customers use `q=restriction:{code}`. Cart search puts `restriction:{code}` in the posted `q`. With no site, those clauses are omitted (`dashboard/src/dashboard/api/base.api.ts`, `dashboard/src/dashboard/api/orderStats.api.ts`, `dashboard/src/dashboard/api/orders.api.ts`, `dashboard/src/dashboard/api/quotes.api.ts`, `dashboard/src/dashboard/api/customers.api.ts`, `dashboard/src/dashboard/api/carts.api.ts`). Returns, products, coupons, vendors, and employees are loaded with no site clause (`dashboard/src/dashboard/hooks/useReturns.ts`, `dashboard/src/dashboard/hooks/useProductsCount.ts`, `dashboard/src/dashboard/hooks/useCouponsCount.ts`, `dashboard/src/dashboard/hooks/useVendorsCount.ts`, `dashboard/src/dashboard/hooks/useEmployees.ts`).

Default range is `last30`. Presets are `last7`, `last30`, `mtd`, and `ytd`; a calendar range becomes `custom`. `last7` is today through six days earlier, `last30` is today through 29 days earlier, `mtd` starts on the local first of the month, `ytd` starts on local 1 January. Stored values are local `YYYY-MM-DD`. Stats requests turn a date-only string into `T00:00:00.000Z` and `T23:59:59.999Z`, so the local calendar day is sent as a UTC day (`dashboard/src/dashboard/helpers/timeRange.helpers.ts`, `dashboard/src/dashboard/components/TimeRangePicker.tsx`, `dashboard/src/dashboard/api/base.api.ts`).

Only order stats and quote stats send `from` / `to`. Order, quote, return, cart, customer, and employee lists ignore the range. Currency sent to stats is `appState.currency`, otherwise the selected site currency. An empty currency omits the query param (`dashboard/src/dashboard/hooks/useOrderStats.ts`, `dashboard/src/dashboard/hooks/useQuoteStats.ts`).

## Layout rules

Load order: a non-empty `md_dashboard_layout` value is shown and the tenant config is still fetched but not applied. With no local layout, key `dashboard_layout` inside `GET /configuration/{tenant}/basic-configuration` is parsed, else `DEFAULT_GRID_LAYOUT`. A load error with no local layout also uses the default (`dashboard/src/dashboard/hooks/useDashboardLayout.ts`).

`parseLayoutValue` keeps items that have string `i` and numeric `x`, `y`, `w`, `h`, drops the rest, and uses the fallback when nothing valid remains. A layout where every item has `w <= 3` and `x < 3` is treated as the old 3-column grid and scaled: `x` and `w` by 8, `h` by 3 (`dashboard/src/dashboard/helpers/layout.helpers.ts`). An id missing from `WIDGET_REGISTRY` renders no card (`dashboard/src/dashboard/components/DashboardGrid.tsx`). Adding a widget that is already present does nothing; a new one is placed at `x: 0` under the current bottom, sized from the registry default span (`dashboard/src/dashboard/helpers/layout.helpers.ts`).

Global save `POST`s `[{ key: 'dashboard_layout', value: layout }]` to `/configuration/{tenant}/configurations`. Any thrown error, including HTTP 409 `ConfigurationConflictError`, is followed by `PUT` of the same key. The `version` field is not sent. `saveToGlobal` swallows the final error into `saveError` and still resolves, and the page then shows the success toast (`dashboard/src/dashboard/hooks/useDashboardLayout.ts`, `dashboard/src/dashboard/api/configuration.api.ts`, `dashboard/src/dashboard/pages/DashboardPage.tsx`). `GET /configuration/{tenant}/configurations/{key}` exists and has no caller under `dashboard/src`.

`WIDGET_REGISTRY` has 30 widgets. `DEFAULT_GRID_LAYOUT` includes 28. `totalCouponsKpi` and `averageQuoteValueKpi` are registry-only until an operator adds them (`dashboard/src/dashboard/data/widgetRegistry.tsx`, `dashboard/src/dashboard/data/defaultLayout.ts`).

## Data on the board

Stats responses always request `compare=true`. KPI and chart code read `gov`, counts, and statuses. `govGrowth` / `totalOrdersGrowth` are on the types. `KpiWidget` can show a comparison percent, and `getComparisonPeriodLabelKey` maps groupBy `d|w|m|y` to a “vs last …” key, but no current widget passes `comparison` (`dashboard/src/dashboard/api/orderStats.api.ts`, `dashboard/src/dashboard/api/quoteStats.api.ts`, `dashboard/src/dashboard/components/KpiMetricWidget.tsx`, `dashboard/src/dashboard/helpers/orderStats.helpers.ts`). KPI money and counts use `values.totals[0]` only. How the API orders multiple currencies is unknown.

| Widget id | Shows | Scope |
|---|---|---|
| `grossRevenueKpi` | `totals[0].gov` as money, or an em dash | site, range, currency |
| `totalOrderCountKpi` | `totals[0].totalOrders` | site, range, currency |
| `averageBasketKpi` | `gov / totalOrders` when `totalOrders > 0`, else an em dash | site, range, currency |
| `revenueOverTime` | bar of `groupedTotals[].gov` | site, range, currency |
| `ordersOverTime` | line of `groupedTotals[].totalOrders` | site, range, currency |
| `avgBasketOverTime` | line of `gov / totalOrders` per bucket, else 0 | site, range, currency |
| `grossQuoteVolumeKpi` | quote `totals[0].gov` | site, range, currency |
| `totalQuoteCountKpi` | `totals[0].totalQuotes` | site, range, currency |
| `averageQuoteValueKpi` | quote `gov / totalQuotes` when `totalQuotes > 0` | site, range, currency |
| `acceptedQuotesKpi` | `statuses.ACCEPTED`, else 0 | site, range, currency |
| `cancelledQuotesKpi` | `DECLINED + DECLINED_BY_MERCHANT + EXPIRED`, else 0 | site, range, currency |
| `quoteVolumeOverTime` | bar of quote `gov` | site, range, currency |
| `quotesOverTime` | line of `totalQuotes` | site, range, currency |
| `avgQuoteValueOverTime` | line of quote `gov / totalQuotes` per bucket, else 0 | site, range, currency |

Chart x labels always run `formatWeekLabel` on `groupedBy.timestamp` (`week {ISO week}/{year}`). The label helper does not branch on `values.groupBy`. Display currency is `totals[0].currencyISOCode` or the first bucket’s `groupedBy.currencyISOCode`, else the site currency, else `EUR` (`dashboard/src/dashboard/helpers/chart.helpers.ts`, `dashboard/src/dashboard/helpers/orderStats.helpers.ts`, `dashboard/src/dashboard/helpers/quoteStats.helpers.ts`, `dashboard/src/dashboard/widgets/GrossRevenueKpiWidget/GrossRevenueKpiWidget.tsx`, `dashboard/src/dashboard/widgets/RevenueOverTimeWidget/RevenueOverTimeWidget.tsx`, `dashboard/src/dashboard/widgets/AcceptedQuotesKpiWidget/AcceptedQuotesKpiWidget.tsx`, `dashboard/src/dashboard/widgets/CancelledQuotesKpiWidget/CancelledQuotesKpiWidget.tsx`). Quote status keys also present on the type and unused by a widget: `AWAITING`, `CREATING`, `IN_PROGRESS`, `OPEN` (`dashboard/src/dashboard/api/quoteStats.api.ts`).

- Abandoned carts (page 10): `status:OPEN`, `customerId:exists`, and `metadataCreatedAt` strictly before now minus 3 days, plus optional site. Columns: cart id link, customer id link, gross `finalPrice`, created. A cart with no `currency` is formatted as EUR (`dashboard/src/dashboard/api/carts.api.ts`, `dashboard/src/dashboard/helpers/cart.helpers.ts`, `dashboard/src/dashboard/widgets/AbandonedCartsTableWidget/AbandonedCartsTableWidget.tsx`).
- Returns (fetch 50, table shows 10): no site and no range. Total KPI uses the count header or body total, with no list-length fallback. ## HTTP rules

Base URL is `VITE_API_URL` with one trailing slash removed. Timeout is `VITE_API_TIMEOUT`, default 30000 ms. A missing base URL, tenant, or token throws before fetch. Headers are `Authorization: Bearer {token}`, `Emporix-Tenant`, and `Accept`. Count calls also send `X-Total-Count: true`. Search posts send `Content-Type: application/json` (`dashboard/src/dashboard/api/base.api.ts`).

`GET` and `HEAD` retry twice on HTTP 429, 502, 503, 504 and on `TypeError`, waiting 500 ms times the attempt index. Timeout abort is not retried. `POST` (cart search, product search, configuration create) is not retried. Collections are a top-level array, or `content`, `data`, or `items`. Status text is fixed English: 401 Unauthorized, 403 Access denied, 404 Resource not found, 429 “Too many requests — please try again later”; other statuses use `Failed to {operation} ({status})` (`dashboard/src/dashboard/api/base.api.ts`). Customers and open carts treat the literal `Access denied` as a no-access state. Other widgets pass the English string through `t(...)`, so a matching translation key is unknown (`dashboard/src/dashboard/widgets/TotalCustomersKpiWidget/TotalCustomersKpiWidget.tsx`, `dashboard/src/dashboard/widgets/OpenCartsKpiWidget/OpenCartsKpiWidget.tsx`).

In-flight dedup (`getOrLoad`) covers order stats, quote stats, customers, last orders, last quotes, orders in progress, and returns. The key is removed when the promise settles. Stats and list keys include tenant and site, and stats also include dates and currency; the token is not part of the key (`dashboard/src/dashboard/helpers/requestCache.helpers.ts`, `dashboard/src/dashboard/hooks/useOrderStats.ts`). Sites, carts, products, coupons, vendors, and employees are not deduped.
