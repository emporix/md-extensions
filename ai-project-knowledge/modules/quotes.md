Management Dashboard (MD) Sales → Quotes as a Vite federated remote, extracted in COP-7116 (`docs/MIGRATED_MODULES.md`). A quote is a Quote Service document a merchant prepares for a B2B company (legal entity and contact) or a B2C customer: lines with prices and discounts, shipping, a validity date, shared as a PDF and approved or declined. Federation name `quotes`, exposes `./RemoteComponent` (named and default), local port `5188` with `strictPort` (`quotes/vite.config.ts`). The module was first rebuilt in MD as `src/modules/quotes` and tested there, then ported 1:1; Tier 1 infrastructure comes from `companies`, pruned to what the module uses. Needs component library ≥ 2.29.0 (`Calendar` `hideOnDateTimeSelect`) and `currency-symbol-map` for the net-price prefix.

## Records

`quotes/src/models/Quotes.model.ts` and `Shipping.model.ts` are MD's shapes (only import paths changed), null-safe since COP-7125: an item's `price` may be absent or null (`priceStatus` `MISSING` / `PRICED`), the quote carries `incompletePricing`, both addresses may be null, and `totalPrice.grossValue` / `taxValue` may be null while the tax is unknown (see **Quote improvement (COP-7125)**).

- **Statuses** (`QuoteStatus`): `CREATING`, `OPEN`, `AWAITING`, `IN_PROGRESS`, `ACCEPTED`, `DECLINED`, `DECLINED_BY_MERCHANT`, `EXPIRED`. "Completed" (read-only) = `ACCEPTED | DECLINED | DECLINED_BY_MERCHANT | EXPIRED` (`helpers/quoteStatus.helpers.ts`). Badges (`components/quotes/QuoteStatusBadge.tsx`: the list column, the status filter, the heading of a completed quote) show the status name of the Quotes user guide in the `QuoteStatusColor` colour, upper-cased by CL `StatusBadge`, whose 0.75rem text (CL ≥ 2.29.1) is the size of MD's PrimeReact badges: Creating, Awaiting, Open, Pending (`IN_PROGRESS`, the customer asked for changes), Accepted, Declined, Declined by Merchant, Expired (`quotes.status.*`). MD showed the API code; the names come from the COP-7116 acceptance criteria. A status without a name shows its code.
- **Transitions the remote makes**: `CREATING` → `OPEN` (Approval tab "create", then back to the list); `OPEN` → `IN_PROGRESS` (Approval tab "Start negotiation", optional `CHANGE` reason and comment; COP-7125); `AWAITING` / `IN_PROGRESS` → `OPEN` (approve) or `DECLINED_BY_MERCHANT` (decline with a required `DECLINE` reason and an optional comment; MD let the reason be empty). Other transitions are made outside this module.
- **Quote reasons** come from the Quote Service (`listQuoteReasonsCall`); only type `DECLINE` is offered when declining. Reasons themselves are edited in the `status-codes` remote.

## API

The quote, price and shipping calls come from `@emporix/api-calls/next` (1.6.0), the others from the package root. All are bound to the host tenant (`useDashboardContext().tenant`, passed to `./next` as `options.tenant`), and the hooks keep MD's results, so the screens stay as in MD:

- `src/hooks/api/quotes.ts`: `listQuotesCall` (table state through `fromDataTableState` from `@emporix/api-calls/primereact`; the site is the first filter, sent as `siteCode:"main"` where MD sent `siteCode:main`; resolves to `{ data, totalRecords }`), `getQuoteCall`, `createQuoteCall` (resolves to the new id), `patchQuoteCall` (JSON-patch style `ADD` / `REMOVE` / `REPLACE` operations, always an array), `deleteQuoteCall`, `generateQuotePdfCall` (a `Blob`), `listQuoteReasonsCall` (one page of 1000, as MD).
- `prices.ts`: `matchPricesCall` (`X-Version: v2`) for new lines and quantity changes; `shipping.ts`: `listShippingZonesCall` with `expand=methods,fees`. That call returns every translation, so the hook keeps the English zone and method names MD got with `Accept-Language: en`: the Preview lists them and saves the method name on the quote. `taxes.ts`: `calculateTaxCall` (root) for gross shipping.
- Client: `src/api/bootstrap.ts` creates it with `createApiCredentials` from `./next` (tenant and token from AppState; `onUnauthorized` is wired for a future host `refreshToken`). Root and `./next` calls share it.
- `customerManagement.ts` (legal entities and contacts), `customers.ts` (customer list for the B2C dialog and the selected customer), `configuration.ts` (tenant `restrictions` and `enableSyncBetweenRestrictionsAndSiteCodes`), `schema.ts` / `mixins.ts` (quote mixins, schema type `QUOTE`), `changelog.ts` (audit log).

## Routes

Hash routes (`src/Quotes.routes.tsx`, paths in `src/constants/paths.ts`, ids URL-encoded):

| Path        | Screen                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| `/`         | List                                                                                                      |
| `/add`      | New quote draft (only General enabled, no quote request)                                                  |
| `/:quoteId` | Quote editor; `?tab=` selects a tab by name (`general`, `products`, `preview`, `approval`, mixin ids, `audit-log`) or by MD's index |
| `*`         | Redirects to `/` (MD showed its not-found page)                                                           |

`add` and `:quoteId` share `pages/QuoteAddEdit.route.tsx`: a tenant guard (a host tenant switch navigates to the list), then `RemountOnParams`, then `QuoteDataProvider`, then the page. Saving a draft on `/add` navigates to `/{newId}`, which remounts the provider and the form. `QuoteDataProvider` loads the quote with `loadLatest`, ignores responses after it unmounts, and on a failed load navigates to the list with an error toast. `Quotes.module.tsx` keys `RefreshValuesProvider` by pathname, so a refresh requested on a quote page never re-fetches the list.

## Permissions

`Quotes Manager` creates, edits (until the quote is completed), approves, declines and deletes; without it the create button and row actions are disabled. The user's quote scopes (`quote.quote_manage`, then `quote.quote_read`) restrict sites (`helpers/restrictions.ts`, `useQuoteRestrictions`). The contact dropdown needs `Companies Viewer`, the products tree view `Categories Viewer`, the audit log tab `Audit Log Viewer`. The remote loads permissions itself (`PermissionsProvider`).

## List

`pages/QuotesList.page.tsx`, `components/quotes/QuotesTable.tsx`, `hooks/useQuotesColumns.tsx`: site select (no "All sites"), create button, lazy table sorted by `metadata.createdAt` descending. Columns: company name, id, created at, total gross, status (dropdown filter over all statuses, shown by name, filtering on the API code); number and date filters as MD. Column visibility under config key `ext_quotes` with quote mixin columns. Row expansion shows the lines (name, quantity, unit, unit price, gross). Row click opens the quote; row and batch delete need manage permission; approve and decline row actions only for `AWAITING` / `IN_PROGRESS` and a manager. The list loads once on entry (MD sent two identical GETs), and a delete reloads the rows and the paginator total (MD kept the total stale).

## Quote editor

`pages/QuotesAddEdit.page.tsx`: tabs General, Products, Preview, Approval, quote mixin tabs, audit log (`entity: quote`). Products, Preview, Approval and the audit log are disabled until a quote id exists. The site select is disabled once a quote is loaded, and loading a quote switches to `quote.siteCode`. Mixin saves patch `ADD /mixins/{key}` and `ADD /metadata/mixins/{key}`. The mixin forms load once per loaded quote (MD requested the schemas and references again on every render), and they are read-only on a completed quote like the other tabs (MD left them editable).

- **General** (`QuotesTabGeneral.tsx`, `helpers/quoteGeneralForm.helpers.ts`): B2B needs a company (`components/shared/CompaniesSelector.tsx` on CL `PaginatedSelector`) and a contact with a customer; B2C needs a customer from `QuoteChooseCustomerDialog` (single-select table). Only addresses tagged shipping / billing are offered; "same addresses" copies shipping into billing. Restriction is required unless the user has full access. Create sends site, currency, customer, optional legal entity, address ids and restriction; edits send only dirty fields as patch operations. Completed quotes show a status box (order, reason, comment); the order number links to the orders remote only with `Orders Viewer` (MD linked it for everyone). Save needs a shipping and a billing address, for B2B and B2C (MD let a quote without addresses save, because the address pickers only exist when there are addresses), except for a B2B company without any location (COP-7125), and on create also a selected site, which gives the draft its site and currency (MD could send a draft without `siteCode`).
- **Products** (`QuotesTabProducts.tsx`, `QuotesSelectProductsDialog.tsx`, `hooks/useQuotesMatchPrices.tsx`, `helpers/quoteItems.helpers.ts`, `helpers/productsBrowser.helpers.ts`): the picked products fill the tab (name, id, remove). For a manager on a non-completed quote a Select products button opens `QuotesSelectProductsDialog`: CL `ProductsBrowser` (list, and tree with `Categories Viewer`) on a draft that starts from the picked products; Apply selection hands the draft to the form, closing the dialog drops it, and no product is loaded before the dialog opens (MD showed the picker on the page, under a list of fixed height). The dialog keeps a height of 90vh and only the table rows scroll; those rules are local SCSS until the component library releases `fixedHeight` / `fillHeight`. Save sends `ADD /items` for new and `REMOVE /items` for dropped lines only; new lines are priced with match-prices (quote currency and site, shipping-address country, item type `PRODUCT`) inside the save's error handling, so a failed pricing call shows the error toast too (MD priced before it).
- **Preview** (`QuotesTabPreview.tsx`, `QuotesTabPreviewTable.tsx`, `helpers/quoteShipping.helpers.ts`): quantity, total and discount recompute each other (a quantity change re-prices the line with match-prices; if that fails, a toast shows `toasts.errorFetchPrices` and the line is recomputed with its current price, where MD left the rejection unhandled); gross per line = net × (1 + tax rate). Shipping methods are the zones of the quote site that ship to the shipping country and have a tax code, filtered by `maxOrderValue` (a failed zones request shows `toasts.errorFetchShippingMethods`; MD left the list empty without a message); the fee is the cheapest one whose minimum order value is reached. Validity uses CL `Calendar` with `showTime`, `hideOnDateTimeSelect` and `minDate`. A net value typed on a line without a quantity stays 0 (`getUnitPriceForNetValue`; MD divided by the zero quantity). Save sends `REPLACE` for the dirty `/validTo`, `/comment`, `/customerReference`, `/items`, `/shipping`; a failed save of Preview or Products shows an error toast (MD only logged it).
- **Approval** (`QuotesTabApproval.tsx`, `QuotesChangeStatus*.tsx`, `helpers/quoteChangeStatus.helpers.ts`): the quote PDF in an iframe (its object URL is revoked once a newer PDF replaces it and when the tab closes; MD never revoked them); "create" for `CREATING`, "Start negotiation" for `OPEN` (COP-7125), approve and decline for `AWAITING` / `IN_PROGRESS`, then a confirm and `REPLACE /status` with `{ value, quoteReasonId?, comment? }` (empty fields stripped). A decline needs a reason of type `DECLINE`: its submit stays disabled until one is picked (COP-7116; MD let it be empty). "Create" sends the quote shown now, and the buttons follow permissions that arrive after the quote (MD kept the first render's quote and permissions, so a deep link to the tab could not send). A failed send, approval or decline, and a failed load of the reasons, show the API message or a translated fallback (MD read `response.data.message` unchecked, which threw without a response).

## Quote improvement (COP-7125)

Ported from MD emporix/management-dashboard#1707 (Łukasz Seremak, 2026-11-19; MD files `src/components/quotes/*`, `quotePricing.helpers.ts`, `useQuotesMatchPrices.tsx`, `useQuoteTaxClasses.ts`), on CL components. A quote can be prepared before prices and addresses are known; the Quote Service accepts it in `CREATING` and rejects `OPEN` / `ACCEPTED` without prices or addresses (400 `QUOTE_ITEMS_WITHOUT_PRICE` / `QUOTE_ADDRESS_MISSING`, toasted with the API message).

- **List and expansion row**: the total is the gross; while it is null the net total shows with " (net)" (`quotes.table.netSuffix`; sorting and filtering still use the gross). An item without a price shows "Price on request" (`components/quotes/PriceOnRequestBadge.tsx`, CL `StatusBadge`; CL has no Tag).
- **General**: a B2B company without any location can be chosen; Locations show "No locations yet - add them before the customer can accept" with the link to the company, and Save works without addresses. The create request and the edit operations omit address ids that are not chosen (`helpers/quoteGeneralForm.helpers.ts`). Companies with locations and B2C customers keep the rule that both addresses are needed. "Same as shipping" is ticked on load only when both addresses exist and are the same (`hasSameAddresses`).
- **Products**: a product without a price list entry is added without `price` (its quantity carries `unitCode: ''`) and is marked "Price on request" in the list. The match country is the shipping-address country, else the first `shipToCountries` entry of the quote's own site (`resolveMatchCountry`); without either, nothing is added and `toasts.errorNoShipToCountry` asks to set ship-to countries (`NoShipToCountryError`). Without a shipping address the price carries only `tax: { taxClass }`, not the fallback country's rate.
- **Preview**: an unpriced row shows "Price on request", an empty net-price field (`enteredNetValues`, never a synthetic price) and no discount. Saving an entered net price sends `REPLACE /items/{itemId}` with the whole item and `price: { type: 'EXTERNAL', totalNetValue }` (plus `tax: { taxClass }` when a class was picked); the whole-list `REPLACE /items` goes first and only when priced rows changed (`buildItemsUpdateOperations` in `helpers/quotePricing.helpers.ts`). A tax class column (`hooks/useQuoteTaxClasses.ts`, the tax service for the address country) appears for unpriced and EXTERNAL rows once the quote has a shipping address; a failed or empty load shows `taxClassesLoadError` / `taxClassesEmpty`. Tax rate and gross show only when the backend returned a rate for every priced row and the quote has a shipping address; otherwise the totals are net. "Totals exclude n unpriced items" shows while `incompletePricing` is true (`components/quotes/UnpricedItemsWarning.tsx`, CL `Message`). Shipping is required only with a shipping address; after a save that moves the totals, a changed shipping fee or method is marked dirty with one `toasts.shippingUpdated` info toast. A method that is no longer allowed is cleared with `shouldValidate`, so Save is disabled until a new one is chosen (react-hook-form 7.91 keeps `isValid` after a plain `setValue`; MD's 7.54 did not need it).
- **Approval**: an `OPEN` quote offers "Start negotiation" (`components/quotes/QuotesStartNegotiation.tsx`): an optional `CHANGE` reason and comment, `REPLACE /status` to `IN_PROGRESS` (`buildStartNegotiationPayload`), then a reload.
- **Tests**: `helpers/quotePricing.helpers.test.ts` and `hooks/useQuotesMatchPrices.test.tsx` are MD's tests on Vitest. All 74 cases of MD's `quotesNullSafe.test.tsx` run in the `QuotesTable`, `QuotesTabGeneral`, `QuotesTabProducts`, `QuotesTabPreview` and `QuotesTabApproval` tests. Cases that an earlier test covered got MD's extra checks there, and the rest sit in `describe('MD quotesNullSafe cases')` blocks under MD's titles. They assert the remote's toast form (the API message as the title). `test/quoteNullFixtures.ts` is MD's fixture. CL `InputNumber` reports a change on each key press, so the tests type with `fireEvent.keyPress` (a value written to the element is only read on blur, which CL does not report).

## Translations

`src/translations/{en,de}/quotes.ts` equal MD's `quotes` namespace (101 keys each) plus the eight status names `quotes.status.*`, `dialog.status.types.*`, `tabs.general.address`, `toasts.errorFetchReasons`, `toasts.errorFetchShippingMethods` and `toasts.errorFetchPrices` (COP-7116), and 19 texts of COP-7125 (negotiation dialog, "Price on request", the unpriced warning in singular and plural, tax class texts, the no-locations hint, `table.netSuffix` and three toasts), 134 keys each. Corrected after the A–Z run: the German decline dialog ("Angebot ablehnen" instead of "löschen", a German confirm question), DE "kann", "Zusätzliche", "freigegeben" after an approval, EN "shipping", and DE `segments` "Benutzer-E-Mail". `segments`, `sites`, `products` and `categories` are subsets of MD keys the screens use; `global`, `mixins`, `auditLog`, `confirmBox`, `errors`, `navigation` come with Tier 1 (DE `deleteConfirm` follows MD master). A few non-visible labels for CL controls were added (`global.clear`, `global.remove`, `products.browser.*`, the PDF iframe title).

## Host wiring

The MD host route `quotes` (`apps/management/quotes/*`) loads this remote from `VITE_QUOTES_URL` (Mode A); `QuotesPathRedirect` moves old pathname deep links (`/apps/management/quotes/{id}?tab=…`, `/add`) into the hash. Links that leave the remote use `window.location.assign`: company `/apps/management/companies#/{id}`, order `/apps/management/orders#/{id}`, cart `/apps/management/carts/{id}` (no `backTo`, it cannot cross the boundary), customer `/apps/management/customers#/{id}` (MD's `customerDetailUrl` since COP-7185; the other remotes still link the old pathname, which MD's `CustomersPathRedirect` rewrites). `SitesProvider` starts from the site MD persisted (`localStorage` `tenant` / `sites` / `currentSite`, only for the host tenant) and never writes back, so a site change inside quotes does not change the host's site.
