## Embedded remote

The host application is not in this repo. The in-repo contract is `docs/MODULE_MIGRATION_PLAYBOOK.md`: federation `name` equals the Management Dashboard route `key` and `ExternalModule.moduleName`; the expose is `./RemoteComponent`; the remote uses `HashRouter` and the host uses `BrowserRouter`; the host env var is `VITE_{MODULE}_URL` pointing at `remoteEntry.js`. `orders/vite.config.ts` and `orders/README.md` repeat that the federation `name` must equal that route key. Those host env files were not read.

Every federated `vite.config` sets `filename: 'remoteEntry.js'` and `exposes: { './RemoteComponent': './src/RemoteComponent' }`. No config exposes anything else. `orders`, `returns`, `brands`, `customer-groups`, `users-and-groups`, `products`, `labels`, `status-codes`, `coupons`, `companies`, and `units` export `RemoteComponent` both as a named export and as default (`orders/src/RemoteComponent.tsx` and `products/src/RemoteComponent.tsx` comment that the host reads `module.default`). `dashboard`, `statistics`, and `agentic-ai` export default only.

The host is expected to render that expose with an `appState` prop. Standalone `index.html` never does: it mounts `#root` and loads `src/main.tsx` (`algolia-synonyms` loads `src/main.jsx`), and `main` renders `App`.

`orders`, `returns`, `products`, and `units` type `appState` as required. `brands`, `customer-groups`, `users-and-groups`, `labels`, `status-codes`, `coupons`, and `companies` default a missing `appState` to tenant and token `default`, language and contentLanguage `en`, and a no-op `onError` (`brands/src/RemoteComponent.tsx`, `labels/src/RemoteComponent.tsx`). `statistics` defaults tenant, language, and token to `default`. `agentic-ai` defaults those three to `default` and `contentLanguage` to `en`. `dashboard` treats missing `tenant` or `token` as a failed boot and renders the text `Missing required configuration (tenant or token).`; otherwise it fills language and contentLanguage `en`, currency id `EUR`, and a user with empty `userId` and `termsAndConditions: true`.

Aligned `AppState` (`orders`, `returns`, `brands`, `customer-groups`, `users-and-groups`, `labels`, `status-codes`, `coupons`, `companies`, `units`, `products` `src/models/AppState.model.ts`): `tenant`, `language`, `token`, optional `currency` (required in `products`), `contentLanguage`, optional `user`, `onError`. No `emporixApiUrl` and no `permissions` field; `products` loads permissions itself and does not call `onError` (`products/src/context/PermissionsProvider.tsx`). `brands/README.md` describes `emporixApiUrl`, `ExtensionProvider`, and `useExtensionContext`; `brands/src/RemoteComponent.tsx` wraps routes in `DashboardProvider`, and `brands/src/api/bootstrap.ts` reads `import.meta.env.VITE_API_URL` only.

Those eleven remotes call `useApiCredentials(tenant, token)` and `i18n.changeLanguage(appState.language)`, then `ToastProvider` → `DashboardProvider` → `PermissionsProvider` → `FeatureTogglesProvider` → `ConfigurationProvider` → `SitesProvider` → `UIBlockerProvider` → `HashRouter`. `orders`, `returns`, `products`, `coupons`, `companies`, and `units` insert `ReferenceOptionsProvider` (custom entities for mixin reference fields) before `UIBlockerProvider`; `products` and `companies` also wrap their routes in `NavigationConfirmProvider`. The blocker import is `./context/UIBlocker` in `orders`, `returns`, `products`, and `companies`, and `./context/UIBlcoker` in `brands`, `customer-groups`, `users-and-groups`, `labels`, `status-codes`, `coupons`, and `units`. What those providers load was not read.

`agentic-ai` keeps `en` and `de` and maps any other `appState.language` to `en`, then `AppStateProvider` → `FeatureTogglesProvider` → `IamScopesProvider` → `ToastProvider` → `HashRouter`. `statistics` calls `i18n.changeLanguage(appState.language)` with the value unchanged and wraps `DashboardProvider` only. `dashboard` does not call `i18n.changeLanguage` in `RemoteComponent`; `DashboardPage` passes `appState.language` into `useTranslation`.
