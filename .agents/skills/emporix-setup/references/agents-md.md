# `AGENTS.md` managed block

`AGENTS.md` is what coding agents load automatically at the start of a session.
Setup owns one block in it, delimited by markers, and never touches anything
else in the file. Humans add their own rules outside the block.

Keep the block short. It is injected into every turn. Detail that an agent
needs only sometimes belongs in `PROJECT.md` / `ai-project-knowledge/` and is
reached through the links and the routing table.

## Write rules

- File missing → create it with the block below as its only content.
- Markers present → replace everything between them, keep the rest byte-for-byte.
- File present, no markers → append a blank line and the block at the end.
- `CLAUDE.md` present without a reference to `AGENTS.md` → report a suggested one-line pointer; do not add it.
- Every row cites a repository path or says `unknown`. No prose approximations of commands. No pasted dependency lists.
- The **Frontend rules** row is present exactly when `standards.frontend` is set, also on `--set` runs that only touch that key.
- Render, diff against the current block, write only when different.

## Working agreements

- Branch and PR flow, Jira keys, and evidence publishing follow the `emporix-*` skills; issues go through Emporix AI Buddy MCP, PRs through `gh`.
- Markdown for the current ticket lives in one folder, `.ai/runs/{ticket-branch}/`, named the same as the branch and starting with the Jira key. That includes the issue plan and any other note (questions for a product owner, a Figma comparison, a decision). Do not put those files in the repo root or commit them. See `emporix-setup/references/runs-layout.md`.
- Keep `ai-project-knowledge/` current: when a change alters business rules, data model, or API, update the matching file in the same PR.
- Never commit `.ai/`; never write secrets into `ai-setup.json` or the knowledge files.
